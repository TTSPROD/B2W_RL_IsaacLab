# B2W: локальный монитор обучения

Запуск из корня репозитория:

```powershell
& ./scripts/run_local.ps1 dashboard/server.py
```

Открыть `http://127.0.0.1:8765`. Сервер слушает только loopback; порт можно
переопределить аргументом `--port`. Для остановки foreground-запуска — Ctrl+C.

Сайт читает `logs/rsl_rl/*/*/continuation_manifest.json`, `progress.json` и
TensorBoard scalar events. Доступны все существующие локальные runs с manifest
и event-файлами. Новые события обновляются каждые 10 секунд; запись event writer
может отставать от `progress.json`. Все scalar points сохраняются, линия EMA
рисуется поверх исходных значений. Hover показывает исходное значение.
Список запусков также обновляется автоматически. По умолчанию сайт переходит
к самому свежему run; ручной выбор в списке закрепляет выбранный run.
Очередь продолжения 23999→24499 читается из
`logs/local_rehearsal500_*/queue_status.json` и видна до освобождения GPU.

Процесс не импортирует Torch, не запускает Isaac и не меняет обучение или логи.
Нет API управления jobs или чтения произвольных файлов. Checkpoints доступны
как список метаданных, без загрузки weights в память. Статус «Нет свежих данных»
означает отсутствие новых updates более 90 секунд; он не доказывает остановку
процесса. ETA рассчитывается по среднему времени выполненных updates.

Ход проверки 23999 читается из `logs/fullcycle23999_validation_20260927/evaluation_progress.json`.
После завершения и проверки traces сайт использует
`docs/results/evidence/fullcycle_23999_20260927/summary.json`: свежие 21999/23999,
а также сохранённый контроль 19999. Контроль выбирается в разделе теста.
До готовности этого файла показывается предыдущая проверка 19999/21999.
Таблица содержит все 234 сценария, отдельные показатели unsafe и физического
stair-stop покрытия. Новые evaluations сайт не запускает.

RL SAR проверяется отдельно по тому же протоколу вместе со свежей 23999.
Прогресс читается из `logs/rl_sar_fullcycle_20260927/evaluation_progress.json`.
После проверки полноты и replay сайт автоматически выбирает
`docs/results/evidence/rl_sar_fullcycle_20260927/summary.json`. В сравнении доступны
RL SAR, сохранённые 19999/21999 и свежий кандидат 23999. Различия повторного
контроля 23999 отражены отдельно; старые summary не изменяются.
Референс — pinned внешний TorchScript, без известного training iteration.
На сайте явно указан общий Isaac adapter и отсутствие проверки C++ runtime RL SAR.
При обновлении данных сохраняются выбранный контроль и фильтры; при появлении
нового завершённого сравнения автоматически показывается его основная пара.

Последующая проверка 24499 использует `logs/fullcycle24499_validation_20260927/evaluation_progress.json`.
После replay приоритет имеет `docs/results/evidence/fullcycle_24499_20260927/summary.json`:
свежие 23999/24499 и сохранённые 19999/21999/RL SAR. В пояснении показано,
сколько из 43 целей восстановлено до прежних full+zero без unsafe, и сколько
из 9 потерянных 32/32 возвращено. Это метрика известных training targets.

Проверка 25000 читается из `logs/fullcycle25000_validation_20260927/evaluation_progress.json`.
После автоматического replay приоритет получает `docs/results/evidence/fullcycle_25000_20260927/summary.json`:
свежие 24499/25000 и сохранённые 19999/21999/23999/RL SAR. Восстановление
92 целей оценивается по лучшим сохранённым full/zero/exposure counts 21999/23999
без unsafe. До готовности summary сайт показывает предыдущие итоги и живой
статус новой проверки. Ошибка postprocessing явно отражается в статусе.

Frontend: статические HTML/CSS/JS в `dist/`, без внешних CDN и сборки.
Backend: стандартная библиотека Python и уже установленный TensorBoard.
Live данные не копируются в Git. Сайт локальный, внешняя публикация не нужна.
