# Где обучать B2W

## Текущее решение

**Первым проверить headless обучение на отдельном настольном ПК с RTX 4070 Ti 12 GB. Ноутбук оставить для разработки и визуальной проверки. Сервер сохранить как копию проекта и кандидат для последующего масштабирования.** Это рекомендация по обследованному оборудованию, сообщению пользователя о втором ПК и upstream требованиям; B2W training benchmark ещё не выполнен.

Настольный ПК предпочтителен для длительных запусков по условиям охлаждения и возможности не занимать рабочий ноутбук; реальное преимущество по скорости ещё не измерено. Пользователь подтвердил обычную RTX4070Ti12GB, Windows11 и Ubuntu26.04. RAM32GB подтверждена; CPU ещё не уточнён. [Спецификации NVIDIA](https://www.nvidia.com/en-ph/geforce/graphics-cards/compare/). Для32GB системной RAM начинать осторожно;64GB даст больше запаса для terrain generation и инструментов. Это ориентир конфигурации, не предложение покупать оборудование.

Первый пилот — Windows11. Ubuntu26.04 не входит в опубликованную матрицу IsaacSim5.1 (Ubuntu22.04/24.04); не считать её подтверждённой платформой без отдельной квалификации. Если Windows dependencies robot_lab станут препятствием, рассмотреть отдельное поддерживаемое Linux окружение без переустановки текущих ОС в рамках подготовки плана.

GitHub на настольном ПК работает штатно: использовать обычный Git без дополнительного навыка обхода DNS.

| Параметр | Локальный ПК | Сервер |
|---|---|---|
| GPU | RTX 4080 Laptop, 12 GiB, RT cores | 4×Hopper, ~94 GiB каждая, NVML не определяет коммерческое имя |
| CPU/RAM | i9-14900HX, 24 cores/32 threads, 32 GB | Xeon6527P, 96 threads, 503 GiB |
| ОС | Windows11 | Ubuntu22.04 |
| Isaac Lab baseline | RT есть; VRAM ниже официальных16 GB; нужен пилот | Без RT нет официальной поддержки Sim5.1; headless ещё не проверен |
| Основное преимущество | Быстрая отладка и единая локальная sim2sim проверка | Потенциально долгие runs/несколько seeds, большой RAM/VRAM |
| Ограничение | VRAM, тепло/TGP ноутбука, занятие ПК | Совместимость runtime, занятые GPU; большой объём VRAM сам по себе не решает |

Установленный локальный Sim5.1 найден, но его IsaacLab привязан к другому editable checkout. Поэтому текущая проверка — инвентаризация, не запуск корректно изолированного B2W runtime. Не утверждаем, что существующее окружение готово для нового проекта.

## Почему 12 GiB стоит попробовать на RTX 4070 Ti или ноутбуке

Официальные требования IsaacLab2.3.2: RAM≥32GB, VRAM≥16GB. При этом опубликованный headless benchmark G1/RSL-RL использует около6.1GB VRAM при4096 средах. Это другая задача, GPU, ОС и модель контактов; число не переносится на B2W. Оно лишь подтверждает, что общий системный минимум не является измерением памяти каждого безкамерного RL workload. [Требования](https://isaac-sim.github.io/IsaacLab/v2.3.2/source/setup/installation/index.html), [benchmark](https://isaac-sim.github.io/IsaacLab/v2.3.2/source/overview/reinforcement-learning/performance_benchmarks.html).

Для первого blind actor не нужны RGB/depth cameras, тяжелая визуализация и тысячи детализированных промышленных решёток. Training запускать headless, GUI validation отдельно. RTX4080 Laptop нельзя оценивать по скорости настольной RTX4080/4090: power limit и длительное охлаждение отличаются.

## Короткий эксперимент для окончательного выбора

1. На настольном ПК подтвердить CPU и свободное место, затем отдельное окружение нового проекта; pinned IsaacLab/robot_lab, проверенный B2W asset, smoke с16–64 средами. Никаких установок поверх найденного старого editable окружения ноутбука. Windows11 предусмотрена IsaacLab, зависимости robot_lab проверяются отдельно.
2. Flat:256→512→1024→2048 сред;4096 только при достаточной памяти. После прогрева собрать минимум200 PPO iterations на каждом допустимом размере и wall-clock/VRAM/RAM; время первого asset conversion фиксировать отдельно.
3. Повторить rough, отдельно startup terrain generation и steady-state. Проверить finite rewards/observations, reset и экспорт/checkpoint resume.
4. Лучший вариант прогнать30–60min для оценки sustained throughput/температуры, без одновременного GUI. Значения — план теста, не выполненное измерение.
5. Умножить измеренное время итерации на целевой бюджет, отдельно учесть eval и3 seeds. При изменении env_count меняется PPO batch: сравнивать total transitions и time-to-quality, а не одинаковое число iterations.
6. Выбрать локальный путь, если реальные run durations удобны и остаётся запас памяти (проектный ориентир≥15%). К серверу возвращаться при дорогих multi-seed runs/perception либо неудобных локальных сроках, после его GPU qualification. Альтернатива — совместимый RTX сервер.

**Неизвестно пока:** сколько часов займёт B2W flat/rough, максимальное устойчивое число сред, будет ли сервер быстрее и вообще запустит ли выбранный headless PhysX runtime. Это устанавливается экспериментом, а не CUDA/VRAM сравнением.
