# Где обучать B2W

## Текущее решение

**На 23 сентября 2026:** длинное дообучение выполняется автономно на четырёх серверных GPU (`inverse57_4gpu_20260923`,4096 сред суммарно), оценка и GUI доступны на локальной RTX4080 Laptop. Предшествующий серверный upstream завершил 20000 updates. Пользователь сохраняет ABI57→16; расширение входов stair-v4 отложено. Настольная RTX4070Ti квалифицирована для своей Flat-линии; её история сохранена отдельно в TRAINING_PROGRESS.md. [Статус/результаты](TRAINING_STATUS.md), [план активного эксперимента](results/2026-09-23-inverse57-overnight-plan.md).

Ниже сохранены локальные измерения и прежние рекомендации по возможному v4; они не означают разрешения менять ABI или запускать v4.

В [pilot 20](results/2026-09-22-4096-env-scaling.md) 4096 сред × 25 PPO-обновлений дали 2 457 600 переходов за 74.35 с против 160.55 с у 1024 × 100. Ускорение training throughput — 2.16×; startup и evaluation сюда не входят. Наблюдаемая VRAM — 6911 MiB из 12282 MiB, не peak. Checkpoint не прошёл stair gate, а число PPO-обновлений различалось. Поэтому 4096 — стартовый кандидат для v4 с новой проверкой peak памяти и sustained throughput; 2048 — запасной режим. Эти данные не задают время до нужного качества.

Настольный ПК предпочтителен для длительных запусков по условиям охлаждения и возможности не занимать рабочий ноутбук; реальное преимущество по скорости ещё не измерено. Пользователь подтвердил обычную RTX4070Ti12GB, Windows11 и Ubuntu26.04. RAM32GB подтверждена; CPU ещё не уточнён. [Спецификации NVIDIA](https://www.nvidia.com/en-ph/geforce/graphics-cards/compare/). Для 32GB системной RAM начинать осторожно;64GB даст больше запаса для terrain generation и инструментов. Это ориентир конфигурации, не предложение покупать оборудование.

Первый пилот — Windows11. Ubuntu26.04 не входит в опубликованную матрицу IsaacSim5.1 (Ubuntu22.04/24.04); не считать её подтверждённой платформой без отдельной квалификации. Если Windows dependencies robot_lab станут препятствием, рассмотреть отдельное поддерживаемое Linux окружение без переустановки текущих ОС в рамках подготовки плана.

GitHub на настольном ПК работает штатно: использовать обычный Git без дополнительного навыка обхода DNS.

После исходной инвентаризации создано проектное `.venv` и локальная копия Isaac Lab v2.3.2. Бинарные пакеты Sim5.1 берутся из `D:\isaacsim51`, поэтому runtime гибридный; его воспроизводимость вне этой машины требует отдельной проверки. Старый editable checkout для текущих запусков не используется. [Фактический runtime](INFRASTRUCTURE.md).

## Почему 12 GiB стоит попробовать на RTX 4070 Ti или ноутбуке

Официальные требования IsaacLab2.3.2: RAM≥32GB, VRAM≥16GB. При этом опубликованный headless benchmark G1/RSL-RL использует около 6.1GB VRAM при 4096 средах. Это другая задача, GPU, ОС и модель контактов; число не переносится на B2W. Оно лишь подтверждает, что общий системный минимум не является измерением памяти каждого безкамерного RL workload. [Требования](https://isaac-sim.github.io/IsaacLab/v2.3.2/source/setup/installation/index.html), [benchmark](https://isaac-sim.github.io/IsaacLab/v2.3.2/source/overview/reinforcement-learning/performance_benchmarks.html).

Для первого blind actor не нужны RGB/depth cameras, тяжелая визуализация и тысячи детализированных промышленных решёток. Training запускать headless, GUI validation отдельно. RTX4080 Laptop нельзя оценивать по скорости настольной RTX4080/4090: power limit и длительное охлаждение отличаются.

## Локальный ресурсный протокол

1. На ноутбуке проверить доступные ресурсы перед run, не останавливая чужие процессы. Для v4 сначала smoke 64–256 сред и save/load; затем короткие probes 2048/4096, без повторения полного старого sweep.
2. При одинаковых physics/rollout параметрах измерить startup, steady-state samples/s, sim/PPO time, peak VRAM/RAM. Ориентир запаса памяти ≥15%; выбирать по измеренному v4 workload, а не старому снимку `nvidia-smi`.
3. На выбранном размере выполнить один teacher pilot. Отдельно учитывать eval и сохранение checkpoint, логировать throughput/температуру в течение run. Если run короче 30 минут, он ещё не подтверждает 30–60-минутную устойчивость; длительную проверку совместить со следующим оправданным продолжением.
4. При 4096×24 начальные 300 updates дают 29 491 200 переходов, предел 1000 — 98 304 000. При 2048 удвоение updates выравнивает число переходов, но меняет PPO batch; зафиксировать это как отдельную конфигурацию. Продление зависит от gates, не от свободного времени GPU.
5. Train/eval и training seeds выполнять последовательно. Исторический режим двух процессов 2048 не является режимом по умолчанию для новой задачи.
6. Для переноса на настольный ПК сначала подтвердить CPU/доступ/место и отдельный runtime проекта, затем повторить тот же smoke/probe и зафиксировать lock. Его преимущество в длительном режиме ещё не измерено; текущую ОС и глобальные пакеты ради плана не менять.

**Неизвестно пока:** время до принятого качества, peak памяти и длительная устойчивость v4 на 4096 средах, скорость RTX 4070 Ti. Qualification прежнего локального B2W не доказывает эти свойства нового teacher/history student. Сервер в рамках корректировки этого плана не опрашивался.
