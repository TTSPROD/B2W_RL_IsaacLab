# Проверка обучения B2W на 4096 средах

Протокол задан 22 сентября 2026 до запуска. По запросу пользователя проверяется масштабирование последней stair-конфигурации pilot 19 с 1024 до 4096 сред на локальной RTX 4080 Laptop 12 GiB. Parent rough seed 54 `model_349.pt`, SHA-256 `916bf5c5b4e5ca43ecfacd4bde6c5a92b164b9c0a6d5c9257a6c7ed68662febf`. Никаких действий с серверными задачами или роботом.

Меняется только `--num_envs`. Сохраняются brake profile 0.7→0.25 м/с на последних 1.2 м, тренировка полного цикла, mixture 30/30% stairs, 10% фиксированных landing starts, 15% flat, 10% random rough, 5% inverse rough, seed 54, PPO settings и parent. Первым выполнить 4096 сред × 1 обновление с reset probes и проверить отсутствие OOM/NaN, конечный actor и фактическую VRAM. При успехе выполнить 4096 × 25 обновлений, то есть **2 457 600 переходов**, тот же sample budget, что 1024 × 100 в pilot 19. Сравнить wall time и transitions/s; 25 и 100 обновлений не эквивалентны по числу шагов оптимизации, поэтому различия качества нельзя приписать только параллелизму.

Checkpoint выбирать не по reward: сначала rough level 9 mesh seed 2006, 512 сред × 1000 шагов, обратные ступени ≥97/102, каждое семейство ≥95%, общая безопасность и tracking в прежних допусках. Только если пройдено — seed 2005, затем открытая stair suite парно с parent. Закрытый набор и sim2sim остаются до выполнения gate. Основной checkpoint rough seed 54 не менять по одному эксперименту масштабирования.

## Smoke

4096 сред × 1 PPO-обновление завершено без OOM и NaN за 4.05 с training time, само обновление 3.43 с, 98 304 перехода. Reset probes: 410/410 выбранных landing starts, 204 inverse rough среды, ноль опасных env-steps за первые 10 после reset и конечные observations. Во время smoke `nvidia-smi` показывал 6363 MiB занято из 12282 MiB (моментальный снимок, не peak). Лог `logs/train_stair20_4096_smoke.log`.

## Обучение с равным числом переходов

Run 4096 сред × 25 PPO-обновлений завершён: 2 457 600 переходов за 74.35 с training time, ≈33.1 тыс. переходов/с. Во время run `nvidia-smi` показывал 6911 MiB занято из 12282 MiB (моментальный снимок). Checkpoint `logs/rsl_rl/unitree_b2w_stair/2026-09-22_13-14-25_stair20_4096_equal_samples/model_373.pt`, SHA-256 `70cebf1fcbb9d90e63385cfe0398530e4560c45e226798768e3a078f9c76cf20`, iteration 373, все веса конечны, actor 57→16. Лог `logs/train_stair20_4096_equal_samples.log`, parent и параметры в `stair_parent.json`.

Для сравнения pilot 19 с 1024 × 100: те же 2 457 600 переходов за 160.55 с, ≈15.3 тыс. переходов/с. Измеренное ускорение по training time **2.16×**. Это один run на каждой конфигурации; порядок update и batch size различаются, а начальная загрузка Isaac Sim в эти времена не входит. Проверка closed-loop ожидается.

## Первый rough gate

Rough level 9, 512 сред × 1000 policy steps на каждом mesh seed:

| Seed | Parent безопасно / inverse | 4096 × 25 безопасно / inverse | RMS vx/vy/yaw нового |
|---|---:|---:|---:|
| 2006 | 506/512; 96/102 | 504/512; 99/102 | 0.236/0.227/0.196 |
| 2005 | 507/512; 99/102 | 505/512; 99/102 | 0.236/0.225/0.197 |

На seed 2006 обычные ступени 101/103, boxes 100/103; на seed 2005 обычные ступени 99/103, остальные семейства ≥95%. Суммарная безопасность ниже parent на 2/512 эпизода на каждом seed (<2 п.п.). RMS tracking на seed 2005 против parent 0.235/0.222/0.195 ухудшился менее чем на 2% по каждой компоненте. Rough gate пройден. Логи `logs/eval_rough_stair20_4096_level9_seed200{5,6}.log`. Открытая stair suite запущена.

## Открытая лестничная оценка

Шесть development строк, по 64 среды × 800 шагов, с одинаковым brake profile:

| Геометрия | Parent проход / цикл | 4096 × 25 проход / цикл |
|---|---:|---:|
| 14/32 см ↑ | 55 / 45 | 55 / 40 |
| 14/32 см ↓ | 60 / 50 | 61 / 50 |
| 16/30 см ↑ | 55 / 51 | 58 / 47 |
| 16/30 см ↓ | 59 / 53 | 60 / 53 |
| 18/27 см ↑ | 55 / 46 | 57 / 45 |
| 18/27 см ↓ | 62 / 51 | 62 / 55 |
| **Итого** | **346 / 296** | **353 / 290** |

Новый checkpoint имеет 25 опасных эпизодов против 19 у parent, 23 недохода против 34, 46 отказов остановки против 35. Получено больше безопасных проходов, но меньше полных циклов; только 3/6 строк не хуже parent по циклу. Требования ≥312/384 циклов, ≥4/6 строк и ≤24 опасных эпизода не пройдены. Логи `logs/eval_stair20_{4096brake,parentbrake}_suite.log`, JSON в `logs/stair_benchmark/stair20_{4096brake,parentbrake}_cycle_*.json`.

**Решение:** 4096 сред на RTX 4080 Laptop работоспособны и дали примерно 2.16× больший throughput при равном числе переходов. Checkpoint не принят; основным остаётся rough seed 54. Оценка seed 55, flat regression, закрытый stair-набор, export parity и sim2sim для него не запускались по заранее заданному stair gate. Из этого сравнения нельзя заключить, что 4096 сред ухудшают качество: у варианта 25 PPO-обновлений против 100, хотя число переходов одинаково. Для следующей структурной постановки можно использовать 4096 как ресурсный режим, но оценивать checkpoint по полному циклу и повторяемости.
