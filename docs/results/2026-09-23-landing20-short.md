# Stair 57→16: короткое landing20-дообучение

23 сентября 2026. Протокол зафиксирован до обучения. Только локальная симуляция; сервер не используется и не опрашивается.

## Гипотеза

У парного 57-D контроля 111 из 169 unsafe и 22 из 46 incomplete приходятся на выходную площадку. Увеличение доли подъёмов ухудшило ascent, а раннее торможение и обратный импульс не прошли screening. Проверяем один фактор: доля фиксированных безопасных стартов на выходной площадке увеличивается с 10% до 20%, поровну для up/down. Общая доля stair остаётся 70%: обычные up/down уменьшаются с 30/30% до 25/25%, landing up/down растут с 5/5% до 10/10%. Flat 15%, random rough 10% и inverse rough 5% не меняются.

Каждый training seed продолжает свой 57→16 control `model_398.pt` с новым optimizer:

- seed 54 parent SHA-256 `49c50eabfc3d9ce640dc3cc46fb15f45fb8f071351e53a768afc2a406b474801`;
- seed 55 parent SHA-256 `f5d7403f98853374b3cdaf6dc329461b29f0f0658e308c0d6a47b890c2371ff2`.

PPO, rewards, brake 1.2/0.25, cycle v3, диапазон ступеней, 2048 сред и seeds 54/55 не меняются. Бюджет ограничен 25 обновлениями; заранее выбран только конечный `model_422.pt`. Промежуточные checkpoints не сравниваются.

## Ворота

1. Smoke 2048×1: actor 57→16, смесь up/down 0.35/0.35, landing 0.20, около 20% landing reset и безопасные первые 10 шагов, inverse reset без unsafe.
2. Rough development mesh 2009/2010: каждое семейство ≥95%, inverse ≥97/102 на каждом mesh и tracking не хуже parent более чем на 10%.
3. Flat seed 1005: 128/128 безопасных, tracking в проектных пределах.
4. Открытая stair suite: оба seed должны улучшить свой parent по полным циклам и ascent, не увеличивая unsafe. Закрытые seeds 4101–4104 не используются.

## Результаты

Первые два smoke завершились до запуска Isaac Sim: сначала устаревшая валидация разрешала inverse rough только при landing fraction ровно 0.1, затем список допустимых parent hashes ещё не содержал явно выбранные control57 checkpoints. Следующие два дошли до reset probe и обнаружили два технических остатка прежнего представления одной landing-колонки: скалярное сравнение и обращение к device через gym wrapper. PPO-обновления и веса во всех случаях не создавались. Проверки переведены на явные множества колонок и unwrapped device.

Рабочий smoke `retry4` прошёл на обоих seed: actor 57→16, по 409 landing env из 2048, 409/409 выбранных landing starts, max height error `5.96e-8` м, 0 unsafe за первые 10 шагов; inverse 102 env, также 0 unsafe. Полные run завершили 25 обновлений:

По направлениям seed 54 изменился `up 262→263`, `down 280→270`; seed 55 — `up 249→233`, `down 315→313`. То есть эффект не повторился: единственный прирост — один цикл на подъёме seed 54, при существенной деградации остальных сравнений. Увеличение статических landing starts не обучило динамический переход с марша на площадку.

**Решение:** оба `model_422.pt` отклонены. Промежуточный `model_400.pt` не оценивается по заранее заданному протоколу. Новые checkpoints не приняты, закрытые stair seeds не использованы. Следующий PPO допустим только после реализации физического roll-in до выходной площадки, чтобы обучающие состояния содержали реальную динамику перехода, а не неподвижный reset.
